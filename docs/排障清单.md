# 排障清单

## 启动失败

- 检查 Node.js 版本是否至少为 20
- 检查根目录、`web/`、`agent/runner/` 是否都已安装依赖
- 重新执行 `npm run build:all`
- 检查 `store/`、`groups/`、`data/` 是否有写权限
- 检查启动日志是否停在数据库初始化、渠道连接还是 Web server 启动
- 如使用 MySQL / PostgreSQL，检查数据库连接配置和网络可达性

## 页面打不开或登录异常

- 检查 `nanoclaw.port`
- 检查是否命中 `EADDRINUSE`
- 检查 `npm run doctor`
- 检查登录开关、账号和密码配置
- 检查请求来源是否被 origin 保护拦截
- 区分"Web UI 不可用"和"后台运行时不可用"，两者不是一回事
- 检查 RBAC 权限是否正确配置（`auth_sessions` 是否有效）

## 聊天无响应

先区分是哪一层断了：

- 入站没进库
  检查渠道日志、`messages` 是否出现新消息、消息是否被 sender trust / trigger 过滤
- 消息进库但没进入处理
  检查 `registered_groups` 是否存在该会话，`GroupQueue` 是否卡住，`lastAgentTimestamp` 是否长期不推进
- Agent 执行了但前端没看到
  检查 WebSocket 是否正常连接，`last_event_seq` 是否被旧事件水位丢弃，是否只有 `assistant_turns` 没有最终 `messages`
- Agent 执行失败后被重试
  检查日志里是否出现 pending cursor 被清理回滚

基础检查项：

- 默认 Provider 是否已配置
- 当前 Assistant 是否启用
- 会话访问策略是否限制了所需目录
- WebSocket 是否正常连接

## 重复回复或重复消费

- 检查渠道侧去重是否命中，例如平台 message id 是否稳定
- 检查 `pendingAgentTimestamp` 是否在恢复时被错误回滚
- 检查是否在已有用户可见输出后又重复触发了一次同会话运行
- 检查 `messages` 和 `assistant_turns` 是否已经存在对应结果

## 标题乱跳或名字不一致

- 优先检查 `custom_title`、`display_name`、`name` 的优先级
- 不要只看单一字段；会话展示名通常不是数据库里某一个原始列的直接映射
- 若渠道 metadata refresh 后名称被覆盖，检查是否把 transport name 错当成用户标题保存

## 前端状态和数据库不一致

- 检查 `last_event_seq` 是否落后
- 检查前端是否还保留 transient turn，而快照尚未追平
- 检查 bot message 是否成功附着到对应 turn
- 检查是否只有 `assistant_turns` 成功持久化，而最终消息未落库

## pending 一直不消失

- 检查 `client_id` / `run_id` 是否完整透传
- 检查归一化后的 pending 内容是否能和持久化消息匹配
- 检查 IPC acknowledgement 是否到达
- 检查是否只写了 turn 事件，但没有最终 bot message 导致 cursor 无法提交

## 文件上传异常

- 检查上传目录权限
- 检查单文件大小与文件数量是否超限
- 检查后端是否能生成文本摘要
- 检查 pending upload 是否最终绑定到了持久化消息

## 任务不执行

- 检查任务是否处于 `paused`
- 检查 `schedule_value` 是否有效
- 检查关联会话和 Provider 是否可用
- 检查 `runtime_claimed_at` 是否长期不释放
- 手动执行一次，判断是调度问题还是底层 Agent/runtime 问题

## Repo Review 不工作

- 检查仓库路径和 Git 环境
- 检查 profile 是否正确绑定
- 检查 hooks 是否成功安装
- 检查 webhook secret 与签名
- 检查 review conversation binding 是否已同步为可执行 group
- 同时查看 run 记录和 branch status，而不是只看某一次 trigger
- 检查 digest 调度是否正常

## 股票分析异常

- 检查数据源状态
- 检查分析配置和预设
- 检查任务队列是否堆积
- 检查新闻源是否可达
- 不要把失败的市场数据请求误判成前端问题

## 浏览器与扩展异常

- 检查浏览器可执行环境
- 检查 Browser API 状态
- 检查 MCP、Skills、扩展安装记录
- 检查是否引入了来源不明的扩展
- 检查是否只是 Web 控制面关闭，而底层 browser service 未被正确停止

## Memory 检索异常

- 检查 scope 是 `group` 还是 `global`
- 检查索引是否已同步
- 检查 identity 与 conversation binding 是否正确
- 检查 context compaction 或 document sync 是否还在追平
- 注意记忆搜索不是完全实时

## 知识库异常

- 检查 `knowledge_bases` 是否存在目标知识库
- 检查 `knowledge_documents` 是否已上传且状态正常
- 检查 `knowledge_chunks` 是否已分块完成
- 检查 Embedding 引擎是否可用（OpenAI / 智谱 / Ollama）
- 检查 `embedding_vectors` 是否已生成
- 检查向量检索配置是否与 Embedding 引擎匹配

## 灵魂与人格洞察异常

- 检查 `user_souls` 是否存在目标用户的 Soul 记录
- 检查记忆提取与合并日志（`memory_extraction_log` / `memory_consolidation_log`）
- 检查 `persona_insights` 是否正常生成
- 检查后台 Soul Consolidation 调度是否正常运行

## Live2D 异常

- 检查 `live2d_models` 是否存在且路径有效
- 检查 `live2d_emotion_mappings` 是否正确配置
- 检查辅助情感分析模型是否可用
- 检查全局与用户级 Live2D 开关状态

## 用户与权限异常

- 检查 `users` 表是否存在目标用户
- 检查 `user_roles` 和 `role_permissions` 是否正确绑定
- 检查 `auth_sessions` 是否过期或无效
- 检查 API route 的权限校验逻辑是否与 RBAC 配置匹配

## 数据库切换异常

- 检查数据库连接环境变量是否正确
- 检查 schema 是否在目标数据库上初始化完成
- 检查 `src/db/sql-adapters.ts` 中 PG_TABLE_PK_COLUMNS 是否注册了相关表
- 如使用 PostgreSQL，检查 SSL 配置（`DB_PG_SSL_REJECT_UNAUTHORIZED` / `DB_PG_SSL_CA_PATH`）
- 检查迁移脚本 `scripts/migrate-to-postgres.ts` 是否执行过
