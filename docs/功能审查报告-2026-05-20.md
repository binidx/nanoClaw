# NanoClaw 全功能审查报告（2026-05-20）

## 审查范围与方法

本次审查按 `docs/repo-feature-map/index.md` 的功能域拆分为 12 个子审查面，覆盖后端运行时、Web/API/DB、安全、Provider、聊天、IM、多渠道、Agent Runner、MCP/Skills、记忆/知识库、Repo Review/CodeMap、任务/Workflow、股票/浏览器/Soul/Tavern/Live2D/分享/终端/诊断等主要功能。审查依据为当前代码实现、产品/架构文档和功能索引；代码是事实源，文档已按当前实现边界做同步更新。本报告后半部分已更新为审查后并行修复完成状态。

## 总体结论

大部分功能模型已经有完整后端路由、持久化模块和前端入口，主体能力基本满足“本地优先 AI 工作台”的设计目标。审查发现的高优先级问题已经完成第一轮并行修复，当前剩余工作主要是收敛新旧双路径、补充更细的端到端验证和清理部分历史架构债。

本次已经更新的文档包括 `README.md`、系统概览、运行与运维、后端运行时、安全模型、Web 控制台、IM E2EE、渠道接入、MCP/Skills、知识库、记忆、助手权限记忆、Repo Review、代码智能图谱、任务调度、Workflow、SDLC Runner Profile、浏览器能力、排障清单、文档索引和 repo feature map。

## 文档同步摘要

- 把 README 的 “WebSocket replay” 改为 “WebSocket live updates with HTTP snapshot backfill”。
- 修正启动生命周期，标明 `loadState()` 和 pending message recovery 是启动屏障，marker files 在 Web server 成功监听后写入。
- 修正 PostgreSQL SSL CA 变量为 `DB_PG_SSL_CA`。
- 标明 `auditMutation` 已写 `admin_audit_log`，关键 mutation 不再只落服务日志。
- 标明 IM E2EE 的当前安全边界：官方前端和后端会阻止 E2EE 链接预览，附件密文性仍依赖官方前端，非 E2EE IM AI 会发送明文上下文给模型。
- 标明多渠道当前生效配置路径是全局 `CHANNEL_INSTANCES`，用户级 channel instance 路径尚未接入主运行时。
- 修正 MCP/Skills 文档：补 `import-json`、registry 服务路径、AppsPageV2 两个主 tab、legacy extension marketplace 与 v2 registry 的区别。
- 修正知识库工具数量、internal endpoint、FTS 候选 + vector rerank 策略和 0.55 vector 融合权重。
- 修正 Repo Review 主表路径、ProjectGraph 社区/Artifact/Repo Review 接入状态。
- 修正任务前端轮询、Workflow role 绑定、模板库和旧 Workteam run route 注册状态。

## 后续优化建议

1. 收敛渠道实例双路径，明确保留全局实例还是把用户级 `/api/user/channels` 接入主运行时，并补跨渠道重启恢复测试。
2. 收敛 MCP/Skills v2 与 legacy extension marketplace 的配置写入路径，避免用户级隔离和全局配置混用。
3. 为上传、IM 附件和知识库导入补统一的孤儿资源回收任务，避免失败路径留下不可见文件或对象。
4. 为任务、Workflow、Repo Review、CodeMap 统一后台作业状态模型，减少轮询、运行状态和取消语义的重复实现。
5. 为 Provider/Assistant 增加密钥轮换、连接探测和会话级 model override UI，降低运行时配置排障成本。
6. 为安全边界补端到端测试矩阵，覆盖 resource binding、assistant-bound KB、share token、IM membership、Tavern avatar 和 Live2D path traversal。
7. 把 WebSocket live update 与 HTTP snapshot 的水位语义写成统一客户端 helper，避免各页面自行处理 `last_event_seq`。
