# 开发与测试

## 技术栈

- 后端：Node.js + TypeScript + Express + WebSocket + 多数据库（SQLite / MySQL / PostgreSQL）
- 前端：React + TypeScript + Vite
- 测试：Vitest
- 向量 Embedding：OpenAI / 智谱 / Ollama

## 目录分工

- `src/`：后端
- `src/db/`：持久化子模块（32 个文件）
- `src/database/`：数据库引擎抽象（SQLite / MySQL / PostgreSQL 引擎、方言适配）
- `src/embedding/`：向量 Embedding（多 provider 支持）
- `src/knowledge/`：知识库（文档分块与检索）
- `src/memory/`：长期记忆层
- `src/browser/`：浏览器 CDP 自动化
- `src/routes/`：46 个 HTTP route 模块
- `web/src/`：前端（16 个主页面 + 子组件）
- `agent/runner/`：本地运行器
- `skills-engine/`：Skills 安装与运行时引擎
- `setup/`：安装与服务化辅助逻辑
- `scripts/`：维护、迁移与校验脚本
- `deploy/`：Kubernetes 部署清单

## 前端控制台架构约束

当前前端不是多 store 架构，而是 `App.tsx` 中心编排 + hooks + 页面/容器组件。开发时应默认遵守：

- 共享远程状态优先放在 `App.tsx`
- 页面组件优先接收 props 和回调，不重复维护一份全局 truth
- 高耦合的网络链路放到 hooks，而不是散落在多个页面

特别是 conversation、status、provider、assistant 这类跨页实体，不要在新页面里各自重新发明状态源。

## 前端实时链路

修改聊天或实时链路时，优先理解并验证以下约束：

- 会话切换依赖 `epochRef` 隔离旧请求
- WebSocket 重连后需要重新订阅当前会话
- 快照回补不能覆盖 transient/live turns
- `last_event_seq` 用于过滤旧事件
- waiting reply 除了 WS 还有轮询兜底

如果这些约束被破坏，最常见的表现是重复消息、pending 不消失、旧会话事件串到新会话、turn 时间线闪烁。

## 与任务页相关的前端约束

任务页当前采用容器 + 页面拆分：

- `TasksPageContainer` 负责远程数据和轮询
- `TasksPage` 负责筛选、编辑器、草稿与展示状态

如果修改任务页，优先保留这条边界，避免把任务页内部交互状态重新提升到 App 层。

## hooks 级测试

当前前端已经有一些关键 hooks 测试，不应忽视：

- `useConversationRealtime.test.ts`
  固定了 `seq` 去重、snapshot 不推进事件水位、transient turn 与 persisted turn 合并、typing/stream 行为
- `useTerminalSession.test.ts`
  固定了"终端容器可渲染前不挂载终端"的设计

修改相关链路后，应优先确认这些行为仍然成立。

## 按改动范围自检

- 后端改动：至少 `npm run build`
- 前端改动：至少 `cd web && npm run build`
- 跨端改动：至少 `npm run build:all`
- memory 相关改动：建议补跑 `npm run test:memory`

## 开发注意点

- 文档必须和代码现状同步
- 不要把历史设计稿当作现状
- 高风险模块改动后，优先验证 Repo Review、任务、终端、扩展、浏览器这些链路
- 修改前端实时链路时，先想清楚是"快照问题""事件问题"还是"状态合成问题"，不要直接在 UI 层打补丁
- 后端大文件已拆分为 barrel + 子模块结构（如 `src/db.ts` → `src/db/*`，`src/agent/agent-runner.ts` → `agent-runner-*.ts`）。修改时编辑对应子模块，barrel 文件仅做 re-export，不应包含业务逻辑
- 新增 schema 字段须同步修改三套 DDL：`src/db/schema-sqlite.ts`、`src/db/schema-mysql.ts`、`src/db/schema-postgres.ts`
- `src/database/` 和 `src/db/` 是两层：前者是引擎抽象（engine / factory / dialect），后者是业务 CRUD 和 schema DDL
- 新增 route 模块后，须在 `src/web/web-server.ts` 中注册
